# ハーネス設計レビュースキル

プロジェクトのAIエージェント制御構造（ハーネス）を5要素で評価する。
ハーネスの品質はモデル性能以上にアウトプット品質を決定する（Morph研究: ハーネス変更±22pt vs モデル変更±1pt）。

## 評価する5要素

### 1. ルール (Rules)
- `CLAUDE.md`（グローバル/プロジェクト）の充実度
- ルールの具体性（曖昧な指示 vs 明確な制約）
- エスカレーションラダー（違反時の対応段階）の有無

### 2. スキル (Skills)
- `.claude/skills/` の定義数と品質
- 繰り返しタスクのスキル化率
- エージェント定義（`.claude/agents/`）の適切さ

### 3. フック (Hooks)
- `settings.json` のPreToolUse/PostToolUse/Stop hooksの設定
- 自動検証（テスト/lint/型チェック）の統合
- イベント駆動の自動化範囲

### 4. メモリ (Memory)
- ナレッジベース（`skills/kb-*`）の充実度
- セッション間の文脈永続化（進捗ファイル等）
- 実験追跡の仕組み

### 5. フィードバックループ
- 自動テスト/検証基盤の有無
- Generator → Evaluator の分離度
- 違反検知 → 修正のサイクル速度

### 6. 出力ズレの学習度
- memory/deviations.md の蓄積量と解決率
- kb-troubleshooting への反映度
- 同一パターンの再発有無
- 「期待/実際/修正」の記録が習慣化されているか

## 評価手順

1. プロジェクトの以下のファイルを全て読み込む:
   - `CLAUDE.md`（全階層）
   - `.claude/settings.json`（グローバル）
   - `.claude/settings.local.json`（プロジェクト）
   - `.claude/skills/` の全スキル
   - `.claude/agents/` の全エージェント
   - `.claude/commands/` の全コマンド

2. 各要素を5段階で評価（L1=未着手, L2=基本, L3=標準, L4=高度, L5=最適）

3. 改善提案を優先度付きで報告

## 出力形式

```

| 要素 | 現在レベル | 目標レベル | 主な課題 |

| スキル | L3 | L4 | レビュー系が不足 |
| フック | L2 | L4 | 自動検証が弱い |
| メモリ | L4 | L4 | 充実している |
| フィードバック | L1 | L3 | テスト基盤不在 |

P0: ...

```
