# ファイル競合マップ作成ガイド

## 概要

並列サブエージェントが同一ファイルを同時変更しないよう、指摘をグループ分けする。

## アルゴリズム

### Step 1: ファイル→指摘のマッピング

各指摘から対象ファイルを抽出し、逆引きマップを作成:

```
file_a.py → [C-001, C-003]
file_b.py → [C-002]
file_c.py → [C-001, C-004]
```

### Step 2: Union-Find でグループ化

同一ファイルを共有する指摘を同一グループに統合:

```
C-001 + C-003 (file_a.py共有)
C-001 + C-004 (file_c.py共有)
→ {C-001, C-003, C-004} が同一グループ
→ {C-002} が独立グループ
```

### Step 3: テストファイルの扱い

- テストファイル（`*test*`, `*spec*`）は競合対象から除外
- ただし、テストのみの修正グループは独立グループとして扱う
- conftest.py等の共有テスト設定は競合対象に含める

### Step 4: ドキュメントの扱い

- ドキュメントファイル（`docs/`, `*.md`）は独立グループにまとめる
- READMEなど複数グループから参照される場合はドキュメントグループに集約

### Step 5: グループ数の調整

- 最大4グループ（サブエージェント上限）
- 5グループ以上になる場合、最小グループ同士をマージ
- マージ時はファイル競合がないことを再検証

## 推奨グループ構成

| グループ | 典型的な内容 |
|---------|------------|
| A: バックエンドコア | routers/, services/, auth, config |
| B: モバイル | apps/mobile/ (hooks, components, screens) |
| C: インフラ/CI | .github/, Dockerfile, docker-compose |
| D: ドキュメント/テスト | docs/, テストのみの変更 |

## 検証チェックリスト

- [ ] 各グループ内のファイルリストに重複がないか
- [ ] グループ間でファイルが重複していないか
- [ ] 推移的依存が見落とされていないか
- [ ] テスト共有設定（conftest.py等）の扱いが正しいか
- [ ] グループ数が4以下か
