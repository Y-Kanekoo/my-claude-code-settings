# 精度向上ハーネス（ワークフロー集）

検証構造（反証多数決・再現ファースト・mutation check・完全性批評）を組み込んだマルチエージェントワークフロー群。
トークンを精度に変換する投資であり、通常モデル（Opus等）のセッションで上位モデル級の精度を出すことを狙う。

## 一覧

| ワークフロー | 用途 | 必須args | 規模目安 |
|---|---|---|---|
| `review-deep` | 多視点レビュー+反証検証。確定指摘のみ返す | なし（`target`: diff/staged/branch/パス配列） | 10〜25体 |
| `bug-fix` | 再現ファースト・バグ修正。再現→仮説→修正→対症療法チェック | `bug`（説明） | 8〜15体 |
| `test-gen` | テスト生成+mutation check（壊して検出を確認） | `target`（ファイル/モジュール） | 8〜14体 |
| `refactor-migrate` | 全件変換+取りこぼしゼロまで反復 | `instruction`（変換内容） | サイト数依存 |
| `design-judge` | 設計N案の独立生成→審査員パネル→統合 | `problem`（課題） | 8体前後 |
| `codebase-map` | サブシステム並列読込→構造化マップ | なし（`focus`で絞込） | 10〜15体 |

複合ハーネス: `/app-dev` スキルが理解→設計→実装→テスト→レビューを上記ワークフローの連結+人間チェックポイントで進める。

## 使い方

```
# 名前で起動（メインセッションから）
Workflow({name: 'review-deep'}, {target: 'branch'})
Workflow({name: 'bug-fix'}, {bug: '保存ボタンを2回押すと重複登録される'})

# 名前解決できない場合（セッション開始後に追加した直後など）
Workflow({scriptPath: '~/.claude/workflows/review-deep.js'}, {...})
```

- 各 `<name>.js` の `meta.whenToUse` に使いどころを記載
- 戻り値は構造化オブジェクト。`status` フィールドで成否と次のアクションが分かる

## 配置の仕様（検証済み 2026-06-11）

- **フラット形式のみ有効**: `.claude/workflows/<name>.js`（`<name>/index.js` のディレクトリ形式は読み込まれない）
- ユーザーレベル `~/.claude/workflows/` とプロジェクトレベル `.claude/workflows/` の両方が有効
- 名前登録は**セッション開始時**。追加直後の既存セッションでは `scriptPath` 指定で起動する

## 規模の調整

- デフォルトは中規模（発見役3〜5・反証役3）
- メッセージに `+300k` のようにトークン目標を付けると、review-deep は新規指摘ゼロになるまで探索を反復する（budget連動）
- args でも調整可: `refuters`, `rounds`, `max_mutants`, `judges`, `depth: 'deep'` など

## ループ運用

各ワークフローは収束ループを内蔵している（新規発見ゼロ・取りこぼしゼロ・mutation全kill まで反復）。
さらに定期実行と組み合わせる場合:

```
/loop 30m review-deep で作業ブランチをレビューして confirmed をレポート
/schedule で夜間に review-deep を実行し、結果をまとめる routine を作成
```

## 設計原則（共通）

- **schema受け渡し**: エージェント間の受け渡しは全て JSON schema で強制（ドリフト防止の最重要点）
- **反証検証**: 発見役の指摘は「反証せよ」プロンプトの独立エージェント多数決を通過したものだけ採用
- **検証ゲート**: コード変更系はテスト・lint通過が完了条件。自己申告の「完了」を信用しない
- **モデル非依存**: `model` は指定せずセッションモデルを継承する
- **回復ルール**: 同一アプローチ3回失敗→異なるアプローチ、さらに3回→TODO(autonomous)付きで構造化失敗を返す
