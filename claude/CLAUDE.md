## Git運用

### コミットガイド
```
[type] 要約（命令形、72文字以内、句点なし）

任意の本文: 変更理由 / 影響や注意点
```

**Type**: `feat`(新機能) / `fix`(修正) / `refactor`(整理) / `docs` / `test` / `chore`(保守) / `ops`(運用)

**ルール**: 1コミット=1目的 / 破壊的変更は `BREAKING:` / docsとコード変更は分離

**例**: `[feat] 収集のマルチプロセス管理を追加する`

### ブランチ戦略
- **個人開発**: trunk 1本（master直push）。危険作業のみ短命ブランチ
- **チーム開発**: main（本番） / develop（統合） / feature/, fix/, hotfix/

## エージェント並列化（Agent tool活用）

### モデル選択
- オーケストレーター・ワーカーとも利用可能な最高性能モデル

### 並列化判断
**並列にする**: 3つ以上の独立サブタスク / 複数領域にまたがる調査 / 異なるファイル群への変更
**直列にする**: 単一ファイル / 強い依存関係 / 小規模変更（〜50行）
**禁止**: 同一ファイルへの同時変更 / ロールバック困難な変更 / 循環依存

### 構成
```
オーケストレーター（メインClaude）
├── Agent(Explore): 調査・コード検索
├── Agent(general-purpose): 実装・複雑なタスク
├── Agent(Plan): 設計・アーキテクチャ検討
└── Bash(run_in_background): テスト・ビルド
→ 結果統合・/review実行
```
ワーカー上限: なし（タスクに必要な数を使用する） / ワーカーはレビュー不要（オーケストレーターがまとめて実行）

### 委譲時の必須情報
目的・出力形式・使用ツール・境界（範囲と制限）

### ワーカー報告
変更点/差分・リスク・未検証事項

### 実行フロー
1. サブタスク特定 → 2. 構成提示 → 3. 承認後に並列実行 → 4. 結果統合 → 5. `/review --staged` → 6. サマリ報告

## Claudeへの指示

### 作業開始時
- 技術スタック確認 / 既存パターンに従う / 変更前に影響範囲を説明

### 作業中・完了時
- コミットは小さく頻繁に（1機能・1修正ごと）
- コード変更後は `/review --staged` を実行
- 重要変更は「現状把握→変更→回帰確認」の流れ
- 新しい技術的知見があれば終了前に `/sync-knowledge` を提案（自動実行しない）

### 提案ルール
**勝手に実行せず提案のみ**: 重複コードの共通化 / 型安全性の追加 / パフォーマンス改善 / テスト追加
**即座に警告**: セキュリティリスク

### 定型作業の効率化ルール
- 繰り返し実行する定型作業が発生したら、**Pythonスクリプト化**または**スラッシュコマンド化**を提案する
- Pythonスクリプト: トークン消費なしで実行可能な状態確認・データ処理等
- スラッシュコマンド: Claudeの判断が必要だが手順が定型化できるもの
- サブエージェント: レビュー等の多角的評価が必要なもの → `agents/` 配下に登録して再利用
- **agents/登録基準**: 2回以上同じ指示で使い切りエージェントを起動した場合、または複数プロジェクトで再利用するパターン → 定義ファイルを作成
- 登録不要: 1回限りの調査、プロジェクト固有の特殊分析
- テンプレート: 繰り返し使うファイル構成は `shared/templates/` 等にテンプレート化

### 出力ズレの記録ルール（全プロジェクト共通）
期待と異なる出力が発生したら、以下の3点セットを記録する:
1. **期待**: 何を期待していたか
2. **実際**: 実際に何が起きたか
3. **修正**: どう修正したか / 今後の防止策

**記録先（重要度順）**:
- L1: CLAUDE.mdのルールに追記（初回）
- L2: kb-troubleshootingに追記（パターン化した場合）
- L3: バリデーションスクリプト/フックに組み込み（繰り返す場合）
- L4: project memory に保存（プロジェクト固有の場合）

**自動化**: PostToolUseフックがバリデーションエラーを検出した場合、memory/に自動記録される

### ハーネス設計ルール（全プロジェクト共通）
新プロジェクト開始時、`~/.claude/templates/harness/` のテンプレートを使用する。
- **方針**: 「最小から足す」（Tier 1 → 2 → 3 に段階的に昇格）
- **Tier 1（必須）**: CLAUDE.md（7セクション構成） + settings.local.json
- **Tier 2（標準）**: + PostToolUseバリデーションフック
- **Tier 3（フル）**: + commands/ + agents/（同じ操作を2回指示したら昇格）

詳細は `/kb-patterns` の「ハーネス設計ガイド」または `~/.claude/templates/harness/README.md` を参照。
CLAUDE.mdが200行を超えたら、詳細をkb-patternsに移して要約だけ残す。

### 禁止事項
- 承認なしの大規模リファクタリング / 既存動作を変える「改善」
- 過度な抽象化 / 不要な依存追加 / 聞かれていないドキュメント生成
