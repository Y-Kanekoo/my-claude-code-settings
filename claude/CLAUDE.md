# Claude グローバル設定

## Intent: 一貫した品質とコミュニケーション
目的: 全プロジェクトで言語・コード・コミットの品質基準を統一する
制約:
- 回答は必ず日本語。コメント日本語 / 変数名・関数名英語
- コミットメッセージ・エラーメッセージ・ログ出力: 日本語
- TypeScriptでは `any` 禁止
- `.env` はコミット禁止、機密情報のハードコード禁止
成功指標: 言語混在ゼロ、型安全性違反ゼロ

## Intent: トークン消費の最小化
目的: Claudeのトークンを判断・設計にのみ使い、実装は外部に委譲する
制約:
- Claudeは設計・判断・レビューのみ。実装はCodexに委譲
- hookは全てcommand type（Claudeトークン0）
- CLAUDE.md合計200行以内。詳細はkb-*に移行
成功指標: agent type hook使用ゼロ、CLAUDE.md 200行以内維持
優先順位: トークン節約 > 自動化の網羅性
詳細: `/kb-harness`

## Intent: 安全で追跡可能な変更管理
目的: 全変更が小さく、追跡可能で、破壊的でないことを保証する
制約:
- コミット形式: `[type] 要約`（feat/fix/refactor/docs/test/chore/ops）
- 1コミット=1目的。破壊的変更は`BREAKING:`
- 承認なしの大規模リファクタリング禁止
- 既存動作を変える「改善」禁止
成功指標: revert不要のコミット率100%
詳細: `/kb-git`

## Intent: 自律的な品質改善
目的: 失敗パターンを自動記録し、再発を防止する
仕組み: 各hook → record_deviation(deviations.md) → analyze-deviations.sh(Stop hook)が3回以上でlearned_rulesに自動昇格
成功指標: 同一パターンの再発ゼロ

## Intent: 安全な並列実行
目的: 独立タスクを効率的に並列処理しつつ、競合を防止する
制約:
- 3つ以上の独立タスクは並列実行
- 同一ファイルへの同時変更は禁止
- 委譲時: 目的・出力形式・使用ツール・境界を明示

## Intent: 予測可能な振る舞い
目的: Claudeが勝手に作業範囲を広げず、提案と実行を分離する
制約:
- **必ずplanを立ててから進めること**（実装前に計画を明示し、ユーザー承認を得る）
- 勝手に実行せず提案のみ（リファクタ、型追加、パフォーマンス改善）
- 既存パターンに従い、変更前に影響範囲を説明
- セキュリティリスクは即座に警告
- 繰り返し作業はスクリプト化/コマンド化を提案
- 過度な抽象化 / 不要な依存追加 / 聞かれていないドキュメント生成の禁止
